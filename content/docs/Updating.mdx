## Why link?

The installer **copies** configs into place, so an installed copy never changes after install. If you instead point your config at a **clone** of the UmmItOS repository with a symbolic link, a single `git pull` keeps things current:

- The **Quickshell** shell updates (and reloads itself).
- The **Discord theme** updates (after a Vesktop reload).

In the shell, **Settings → Update** shows whether the shell is linked and offers a **Pull** button. If the shell is still a copy, it shows a warning with a **Copy command** button that copies the `ln` command below.

## From Settings

Two Settings pages handle updates without the terminal:

- **Update**: lists pending system updates (checking is manual, via **Check**), runs a full upgrade, and pulls the latest UmmItOS from the linked folder. Pull is disabled while an upgrade is running and times out after 60 seconds.
- **Packages**: lists the installer packages that are missing on your system and installs them in one click.

Run it with `Super + Shift + Return`, the bar's update button, or `update.sh` directly. The bar button wears a dot while updates are waiting. It is a colour terminal interface:

- An **Arch news box** at the top shows the five newest items from the [Arch Linux news feed](https://archlinux.org/feeds/news/). Each row is a clickable link, and the box caches the feed for 30 minutes.
- **Pacman and AUR are separate steps.** Tick the steps to run, then press `y` on a row to give that step auto-yes. Pacman can still prompt you while the AUR step runs unattended.
- When it finishes, a **Status box** reports this run and the one before it, how many packages were upgraded, added, and removed, what is still waiting, and whether a reboot is due for a new kernel.

After an upgrade, it asks whether to return to the shell instead of closing.

The shell also checks for Arch news a while after login and every few hours. A new item from the past week is sent once as a critical notice.

## Health check

Press `Super + H` to run a health check (`doctor.sh`). It reports, without changing anything, whether:

- the repo and its submodules are present,
- the shell is linked to the repo and loaded cleanly,
- `~/script` and `shortcuts.lua` match the repo,
- packages, the input method, dotfiles, autostart, and services are in order.

The only repair it makes is `doctor.sh --fix scripts`, which copies the repo's scripts to `~/script`. It also runs once quietly at shell start and sends a notice only on a failure.

<Callout type="info">Run the health check first after a `git pull` on another machine, to catch anything the pull left out of step.</Callout>

## Clone the repository

Clone with submodules (the wallpapers are a submodule):

```shell
git clone --recursive https://github.com/UmmItOS/UmmItOS ~/UmmItOS
```

<Callout type="info">Any folder works; `~/UmmItOS` is just an example used throughout this page.</Callout>

## 1. Quickshell (the desktop shell)

Link the shell config. This replaces the installed copy, so back it up (or remove it) first:

```shell
# Only if it is a real folder, not already a link:
mv ~/.config/quickshell/ummitos ~/.config/quickshell/ummitos.bak

mkdir -p ~/.config/quickshell
ln -sfn ~/UmmItOS/configs/quickshell ~/.config/quickshell/ummitos
```

Restart the shell once (it starts automatically at login afterwards):

```shell
qs kill -c ummitos && qs -c ummitos -d
```

Update later:

```shell
cd ~/UmmItOS && git pull
```

…or use **Settings → Update → Pull**.

<Callout type="warn">Do **not** link `~/.config/hypr`. It holds your own values (monitor layout, etc.) and stays a copy. After a `git pull` or branch switch, the running shell can stay on the old code; if it doesn't reload, run the restart command above.</Callout>

## 2. Discord theme (Vesktop + Vencord)

The theme file lives in the repo at `configs/vesktop/themes/ummitos-style.css`. Its title bar reads **UmmItOS**. It is built on [CapnKitten's Material Discord](https://github.com/CapnKitten/BetterDiscord), which it loads from `capnkitten.github.io` at runtime, so Discord needs internet on start.

### Flatpak Vesktop (`dev.vencord.Vesktop`)

```shell
mkdir -p ~/.var/app/dev.vencord.Vesktop/config/vesktop/themes
ln -sfn ~/UmmItOS/configs/vesktop/themes/ummitos-style.css \
  ~/.var/app/dev.vencord.Vesktop/config/vesktop/themes/ummitos-style.css

flatpak override --user dev.vencord.Vesktop \
  --filesystem=$HOME/UmmItOS/configs/vesktop/themes:ro
```

<Callout type="info">Flatpak can't follow a link out of its sandbox without that read-only permission. Grant only the themes folder, not the whole repo.</Callout>

### Native (non-Flatpak) Vesktop

The themes folder is `~/.config/vesktop/themes/` and no override is needed:

```shell
mkdir -p ~/.config/vesktop/themes
ln -sfn ~/UmmItOS/configs/vesktop/themes/ummitos-style.css \
  ~/.config/vesktop/themes/ummitos-style.css
```

### Enable it

In Vesktop → **Settings → Themes**, tick **UmmItOS Theme**. Turn window transparency **off** (Vencord settings) so it stays solid.

<Callout type="warn">Fully quit and reopen Vesktop the first time so the Flatpak override applies. After later `git pull`s, press `Ctrl+R` to reload the theme.</Callout>
