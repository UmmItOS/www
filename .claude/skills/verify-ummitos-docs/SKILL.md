# Verify the UmmItOS docs site

You are proving behavior of a **static Next.js 16 + Fumadocs docs site**: the homepage (`/`), MDX docs pages (`/docs/**`, from `content/docs/`), a Changelog built from the GitHub Releases API, embedded clips and screenshots, and site search. There is no login, database or user data. The site is read-only, so verification never mutates app state; the only files a run creates live under `.verify/` (gitignored).

All helpers live in this skill's `scripts/` folder. Run every command from the repo root, with:

```sh
S=.claude/skills/verify-ummitos-docs/scripts
```

## Quick start

```sh
$S/launch.sh                                  # build if stale, serve on 127.0.0.1:3100
$S/doctor.sh                                  # must end with: DOCTOR: OK
$S/drive.mjs <label> 'goto|/docs' ...         # drive it like a user (see Drive)
$S/capture.sh /docs/Changelog changelog-static   # static DOM + screenshot of one page
$S/expect.sh <file.dom.html> 'text' '~regex'  # assertions over a captured DOM
$S/media-check.sh                             # every image/video the pages reference is served
$S/cleanup.sh                                 # stop what you started; evidence is kept
```

Then pick the recipe for the feature you changed in [`features/README.md`](features/README.md). A proof that drives one convenient entry point is incomplete when the map lists others.

## Launch

`$S/launch.sh [--port 3100] [--rebuild]`

- Builds into its **own dist dir** (`NEXT_DIST_DIR=.verify/next`) only when that build is missing or older than the sources (`src`, `content`, `public`, `next.config.mjs`, `source.config.ts`, `package.json`, `bun.lock`, `tsconfig.json`). `--rebuild` forces it. A build takes roughly 10 to 60 seconds.
- Starts `next start -p 3100 -H 127.0.0.1` in its own session. State: `.verify/run/server.pid`, `port`, `run-id`, `build-rev`, `server.log`.
- **Ready** means `GET /` answered 200 within 60 seconds. It prints `ready http://127.0.0.1:3100 rev=<sha>[+dirty] run=<id>`. `+dirty` means uncommitted changes under `src`, `content`, `public` or `next.config.mjs` are in the build.
- From a clean checkout it needs `bun install` done once. `.source/` is generated by `fumadocs-mdx` during install and build. The build also needs the network (GitHub Releases for the Changelog) and full git history (the per-page "Last updated" line).
- A custom dist dir makes `next build` rewrite the tracked `tsconfig.json`. The launcher snapshots it and restores it (mtime included), so a run leaves no diff. If `git status` shows `tsconfig.json` modified after a run, that restore failed: `git checkout -- tsconfig.json`.
- **Isolation.** It never touches `.next` or a dev server on `:3000`, and binds only to loopback. There is **one instance per checkout** (state is in `.verify/run`); a second `launch.sh` reports "already running". For parallel runs use a separate `git worktree`. Never drive an instance this run did not start.

## Doctor

`$S/doctor.sh` is read-only and answers "is this instance worth driving?". Run it first, and again whenever anything looks off. It checks: the pid is alive; port 3100 is **owned by that pid**; the build revision against `HEAD`; the build is not stale; `/`, `/docs`, `/docs/Installation` and `/docs/Changelog` return 200; and whether `api.github.com` is reachable (WARN only). It ends `DOCTOR: OK` or `DOCTOR: FAIL` and exits non-zero on FAIL. Feature health, such as whether search returns results, is deliberately **not** in the doctor: it belongs to the feature recipes so one broken feature cannot block the rest.

## Drive

Pick the lightest tool that proves the behavior:

| Need | Tool |
|---|---|
| Click, type, press keys, expand things, follow links | `drive.mjs` |
| Static page evidence (DOM + screenshot) and text assertions | `capture.sh` + `expect.sh` |
| Every referenced image or video is actually served | `media-check.sh` |

**`drive.mjs <label> <step>...`** launches its own headless Chromium (own profile, stopped when it ends), runs the steps in order and stops at the first failure, saving `<label>.fail.png` and `<label>.fail.dom.html`. A step is `name|arg|arg`; quote it, since `|` separates the arguments.

| Step | Meaning |
|---|---|
| `goto\|/docs/Changelog` | open a site path and wait for load |
| `waitfor\|css[\|ms]` | wait until the selector exists (default 8000 ms) |
| `click\|css` / `click-text\|css\|substring` | click the first match / the first match whose text contains the substring |
| `press\|/` | keypress on the page: `/`, `Escape`, `Enter` or one character |
| `type\|install` | type into the focused element |
| `assert-count\|css\|>=\|20` | match count; operators `== >= <= > <` |
| `assert-text\|css\|substring` | first match's text contains it |
| `assert-url\|/docs/Packages` | path starts with it (waits up to 5 s) |
| `assert-js\|expression` | page JavaScript must be truthy (may contain `\|`) |
| `count\|css`, `text\|css`, `sleep\|ms` | print a count / print text / wait |
| `shot\|name`, `dom\|name` | save `<label>.<name>.png` / `.dom.html` |

**Stable handles on this site** (prefer these over position or coordinates): `#nd-sidebar` (sidebar), `#nd-page` (page body), `#nd-sidebar a[data-active="true"]` (current page), `button[data-search-full]` and `input[role="combobox"][aria-label="Search"]` (search), `#fd-search-list` (results, `hidden` when empty), `details > summary` (Changelog notes), `button[aria-label^="Play"]` (YouTube lite embed), `video[autoplay][muted][loop][playsinline]` and `figure figcaption` (clips and stills). Page text is the best handle for content.

**`capture.sh <path> <label> [--size 1500x2000] [--budget 5000] [--no-shot] [--no-dom]`** writes `<label>.dom.html` (DOM after scripts ran) and `<label>.png`. `--budget` is virtual time in ms for client fetches and icon requests to finish. **`expect.sh <dom> <needle>...`**: `text` must appear, `!text` must not, `~regex` must match, `!~regex` must not; it saves `<dom>.expect.txt` and exits 1 on any failure.

## Evidence

Everything a run proves lands in **`.verify/evidence/<run-id>/`** (gitignored, and never deleted by cleanup):

- `<label>.steps.txt`: the transcript, one PASS or FAIL line per step.
- `<label>.<name>.png` / `.dom.html`: screenshots and DOM; `<label>.fail.*` on a failure.
- `*.expect.txt`, `media-check.txt`, `INDEX.tsv`, and `server.log` (copied in at cleanup).

Proof standards:

- **Exercise the real user path.** Search is proven by opening the dialog and typing, not by fetching `/api/search`. Navigation is proven by clicking the sidebar link, not by requesting the URL.
- **Capture the action and the resulting state**, not just the final screen: the transcript plus a screenshot that shows the app (title or sidebar visible).
- **Add a second view** where one exists: `gh api repos/UmmItOS/UmmItOS/releases/latest --jq .tag_name` against the homepage badge; `git log -1 --format=%cI -- content/docs/<file>` against "Last updated"; `curl -I` for an asset.
- **No mocks.** The site calls real services (GitHub, Iconify, YouTube). If one is unreachable, report the unmet precondition; do not count that run as a pass.
- There is **no dry-run or test mode**, and nothing to restore: the site is read-only.
- Report the build revision from `launch.sh`, the evidence paths, and any feature you did not drive, with the reason. Never report a skipped entry point as verified through another path.

## Cleanup

`$S/cleanup.sh [--purge]` signals only the process group of the pid recorded by `launch.sh` (never by process name), copies `server.log` into the evidence folder, removes run state and browser profiles, keeps `.verify/next` so the next launch is fast (`--purge` deletes it), and confirms the port is released. Run it after a failed attempt too, so nothing is stranded. To check that no browser was left behind use `pgrep -x chromium`; `pgrep -f` matches your own shell and gives false alarms.

## Gotchas that apply everywhere

- **Never rebuild into `.next` while a server is serving from it.** The running server then answers 404 for every `/docs/*` page. This skill avoids it by using `.verify/next`; if you build by hand, restart the server afterwards.
- **Do not free a port with `fuser -k` or `pkill next`.** It kills other people's servers. Use `cleanup.sh`.
- **Content moves daily.** Release versions, dates and counts change. Assert patterns (`~v[0-9]+\.[0-9]+\.[0-9]+`), never a literal version.
- **Network dependencies.** Build time: GitHub Releases API (Changelog). Browser runtime: `api.github.com` (repo card on the Overview page), `api.iconify.design` (every icon), `youtube.com` and `img.youtube.com`. Offline, icons render blank and the Changelog shows its fallback; report that as an unmet precondition. The unauthenticated GitHub limit is 60 requests an hour, and `doctor.sh` shows what is left.
- **Videos autoplay, so a screenshot shows a mid-clip frame.** Prove clips by markup, served assets and a decode check (`assert-js` with `readyState`), not by a visual match.
- **`Last built` on the homepage is the time of the isolated build**, not production's. "Last updated on" needs full git history.
- The pre-commit hook runs a full `bun run build`; it is unrelated to verification.
